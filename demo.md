# Demo Idea

With this demo idea I want to try out and generate conversations to try the idea of reliable context compaction. This demo consists of an interactive app that represent a conversation between a user and the system. The topic of the interaction is flowers and how do they mix into potions. In it the user has three possible inputs - an image with flowers, which an instance segmentation model breaks down into different flowers and their counts, a question (which can or cannot be related to the flowers in the previously given images), and a demand to brew a potion with several flowers.

The images should invoke a call to the instance segmentation tool, which counts and identifies all flowers in the image and stores them as the user's inventory. When a new flower in an image is discovered (not present in the knowledge base yet), the agent should invoke a search tool which searches for info in a corpus for the flower. This info is collected, and is saved in the knowledge base.

The questions should invoke a call to a knowledge base where two things can happen: when the user asks for a flower present in the knowledge base, the system returns the info for it as an answer; otherwise it returns a negative answer (i.e. this flower has not been discovered yet).

The demand for brewing of a potion is the following: the user specifies which flowers they want to combine into a potion. The agent cheks whether they have these flowers from previously shown images (are all the flowers present in the inventory). Then uses a combination script that creates a potion. Different flower combinations and quantities yield either positive, negative and neutral outcomes. The neutral outcomes just fail to make a potion (i.e. the combination of X of flower_1 and Y of flower_2 does nothing) and no new info is gained. A positive outcome is creating a potion that grants a positive effect (the effects are - boost happiness by some %, productivity by some %, strength by some % cures disease X and more than one effect can be present). The negatives are opposite of the positive. Sometimes a potion can have both positive and negative effects, but if it's the same they cancel out. This all happens through the potion brewer function and its hidden to the agent; the agent receives only the results. If the potion has negative or positive effects, this info is added in the knowledge base (for example combining 2 flower_1 with 1 flower_3 yields a potion that boosts strength by 5% - this is added as a known fact to the knowledge). This later can be reused so that the agent can help the user craft better potions.
